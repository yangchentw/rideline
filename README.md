# 騎點 RIDELINE

以手機操作為主的單車騎行路線與點名系統。主辦者建立活動、上傳 GPX 路線並設定打卡點；參加者用自選名稱加入，抵達時掃描 QR Code，留下各站的打卡時間。

**網站作者：YangChen**

**正式網站：[rideline.yangchentw.workers.dev](https://rideline.yangchentw.workers.dev/)**

## 主要功能

- **活動金鑰**：每個活動可設定獨立金鑰，提供現場人員顯示、下載與列印 QR Code，不能管理活動或打卡點。
- **活動管理**：建立活動名稱、日期、出發時間與說明，支援多活動切換。
- **GPX 路線**：上傳軌跡檔、顯示地圖與估算總里程，並可下載活動路線。
- **打卡點管理**：每個活動可設定 1–30 個打卡點，支援新增、編輯、刪除與自動依路線里程排序。
- **Google Maps 解析**：貼上地點連結，解析其中的名稱與經緯度，也支援展開部分短網址。
- **介面快速打卡**：加入活動後開啟手機相機掃描站點 QR Code，確認姓名與站點後紀錄時間。
- **QR Code 打卡**：每站產生獨立 QR Code，可下載或列印；重複打卡保留首次抵達時間。
- **參加者名單**：自行取名加入，同一活動不可使用重複名稱。
- **活動統計**：顯示參加人數、已出發人數、完成騎行人數及各站未到名單。
- **抵達時間與匯出**：總覽表格在打卡標記下方顯示時間，可匯出 CSV。
- **響應式介面**：支援手機與桌機，繁體中文介面，時間固定顯示為台灣時間。

## 使用流程

### 主辦者

1. 開啟網站，點選「主辦者登入」，輸入已設定的主辦者金鑰。
2. 點選「建立活動」，填入活動資訊並上傳 GPX，可選填 6–64 字的活動金鑰。
3. 確認打卡點名稱與位置。預設站點是依軌跡點數等分產生，請調整為實際集合或補給位置。
4. 在「打卡點管理」新增、編輯或刪除站點，也可貼上 Google Maps 地點連結。
5. 分享活動連結，下載或列印各站 QR Code，放置於現場。
6. 從活動總覽或參加者名單查看進度、未到名單與抵達時間，必要時匯出 CSV。

### 參加者

1. 開啟主辦者分享的活動連結，確認活動後點選「加入活動」。
2. 輸入 1–30 字的騎行名稱。
3. 抵達打卡點時，在活動介面點「快速打卡・掃描 QR Code」，允許網站使用相機，再將相機對準現場站點的 QR Code。也可用手機相機掃描現場 QR Code，以同一瀏覽器開啟。
4. 確認姓名與站點後，點選「確認抵達，立即打卡」，看到成功畫面即完成。

快速打卡與 QR Code 打卡都需要按下確認，不會因開啟連結就自動紀錄。網站內相機掃描與手機原生相機掃描共用同一筆站點紀錄，保留首次抵達時間。相機掃描需使用 HTTPS 正式網址（本機 localhost 也可測試），只會要求相機權限，不使用麥克風。關閉掃描視窗或讀取成功後會停止相機；畫面影像在瀏覽器內解析，不上傳伺服器。共用模式的抵達時間由伺服器產生，活動資料約每 15 秒更新。

## 金鑰與 QR Code 權限

| 金鑰 | 可使用的功能 |
| --- | --- |
| 主辦者金鑰 `ADMIN_KEY` | 建立活動、管理打卡點、設定或更換活動金鑰，以及使用所有活動的 QR Code |
| 活動金鑰 | 僅顯示、下載或列印所屬活動的 QR Code |

建立活動時可設定活動金鑰，也可由主辦者在「打卡點管理」點「設定活動金鑰」或「更換活動金鑰」，替既有活動設定。

現場人員點選某站「顯示 QR」後輸入活動金鑰，即可解鎖。同一分頁會暫時記住該活動金鑰；切換活動時需要對應活動的金鑰。每次開啟 QR Code 都會重新驗證，原金鑰在更換後無法再次取得 QR Code。已下載的 QR Code 不會因此失效。

正式資料庫僅保存活動金鑰的 PBKDF2 雜湊與隨機鹽值，活動清單不會回傳金鑰、雜湊或公開站點憑證。活動金鑰不影響參加者加入活動、快速打卡或掃描 QR Code 打卡。

## 技術架構

| 用途 | 技術 |
| --- | --- |
| 前端與建置 | React、Vite |
| 地圖 | Leaflet、OpenStreetMap 圖磚 |
| 圖示與 QR Code | Lucide React、qrcode、[jsQR](https://github.com/cozmo/jsQR) |
| API 與靜態網站 | Cloudflare Workers |
| 共用資料庫 | Cloudflare D1（SQLite） |
| 測試 | Node.js test runner、記憶體 SQLite |

同一個 Worker 提供前端與 `/api/*`，D1 保存活動、參加者與打卡紀錄。主辦者操作以 `ADMIN_KEY` 驗證，參加者以加入活動時取得的識別權杖打卡。

## 環境需求

- Node.js **22.13 以上**，建議使用受支援的 LTS 版本。
- npm。
- 部署時需要 Cloudflare 帳號及 Workers、D1 操作權限。

Wrangler 已列為專案開發依賴，不需要額外全域安裝。

## 本機開發

先進入專案目錄並安裝鎖定版本的依賴：

```sh
npm ci
```

### 方式一：前端示範模式

```sh
npm run dev
```

開啟 [http://localhost:5173](http://localhost:5173)。此模式不需要 Cloudflare 登入，活動與打卡資料保存在目前瀏覽器的 `localStorage`，不會跨手機同步。

首次開啟會載入「二輪雙十・中墾騎行」，包含約 311.5 km 路線、12 位示範參加者及模擬打卡紀錄。這些資料不代表實際騎行紀錄，也不會自動上傳正式環境。

### 方式二：本機共用後端

在專案根目錄建立 `.dev.vars`，填入本機測試用的金鑰：

```dotenv
ADMIN_KEY=請替換為自己的本機測試金鑰
```

接著執行：

```sh
npm run db:local
npm run dev:shared
```

開啟 [http://localhost:8787](http://localhost:8787)。此模式由本機 Worker 與本機 D1 提供服務，初始沒有活動，需要登入主辦者並自行建立。

`db:local` 不會修改遠端資料庫。開發資料保存在 `.wrangler/`，`.dev.vars` 與 `.wrangler/` 都已排除於 Git 之外。

## GPX 範例

範例統一存放在 [`public/gpx/`](public/gpx/)，目前包含：

- [`二輪雙十中墾.gpx`](public/gpx/二輪雙十中墾.gpx)：本機示範路線，共 6,968 個軌跡點。

新增範例可直接放入同一目錄，建置後可透過 `/gpx/檔名.gpx` 下載。正式活動仍需在「建立活動」中選取 GPX 上傳。

解析支援 GPX 的 `trkpt` 與 `rtept`。超過 15,000 點的路線會取樣以降低資料量；里程依座標估算。

## Google Maps 連結

支援含有明確地點座標的連結，例如地點網址中的 `!3d緯度!4d經度`、`q=緯度,經度(名稱)`、`query=緯度,經度`。短網址由本機或 Worker 後端嘗試展開，共用模式需先登入主辦者。

解析結果請先確認再儲存。以下情況需要手動補上名稱或座標：

- 網址只有地點名稱或 Place ID，沒有經緯度。
- 網址只有 `@緯度,經度` 地圖視角中心，無法確認真正地點位置。
- Google 沒有提供可讀取的轉址，或分享連結格式無法辨識。

目前未串接付費 Places 或 Geocoding API，不保證所有 Google Maps 分享連結都能解析。

## Cloudflare 部署

### 更新目前的正式網站

本專案已設定正式 Cloudflare 帳號與 D1，並已建立資料表、設定 `ADMIN_KEY`。沿用目前環境更新網站時，不需要重新建立資料庫或重新設定金鑰。

```sh
npx wrangler whoami
npm run db:remote
npm run deploy
```

本次活動金鑰功能新增 `event_keys` 資料表，首次更新此版本前需要執行 `db:remote`；它使用 `CREATE TABLE IF NOT EXISTS`，會保留既有活動與打卡紀錄。之後若無資料表變更，只需部署。

`deploy` 會依序檢查設定、驗證登入、執行測試、建置並發布 Worker。更新網站不會清空 D1 資料。

只想檢查、不發布時使用：

```sh
npm run deploy:check
```

### 部署到自己的 Cloudflare 帳號

1. 執行 `npx wrangler login`，再用 `npx wrangler whoami` 確認帳號。
2. 在 `wrangler.jsonc` 修改 `account_id` 與 Worker `name`，並設定自己的資料庫名稱。
3. 執行 `npx wrangler d1 create rideline-db`。若使用其他名稱，請替換此命令及 `package.json` 的資料庫指令。
4. 將回傳的 `database_id` 填入 `wrangler.jsonc`，保留資料庫綁定名稱 **`DB`**。
5. 初始化資料表並設定主辦者金鑰：

   ```sh
   npm run db:remote
   npx wrangler secret put ADMIN_KEY
   ```

   `ADMIN_KEY` 是固定的變數名稱。執行後，依終端機提示輸入自己設定的密碼；這就是網站「主辦者登入」使用的金鑰。

6. 執行 `npm run deploy`，使用輸出中的 `workers.dev` 網址開啟網站。

正式環境預設沒有示範活動。請建立真實活動，確認正式網址後再分享及列印 QR Code。只上傳 `dist/` 靜態檔案無法提供多人共用功能。

部署、備份與跨手機驗收步驟詳見 [`docs/deployment.md`](docs/deployment.md)。

## 資料與使用限制

- **身份保存在瀏覽器**：沿途請使用同一個瀏覽器。清除網站資料、換手機或改用其他瀏覽器，目前無法找回原參加者身份。
- **需連線才能打卡**：尚未提供離線打卡及恢復連線後補送。
- **不驗證 GPS 距離**：打卡需要有效 QR Code 中的站點憑證，但不驗證現場位置。持有有效打卡連結的人也可開啟並打卡。
- **活動資料可公開查看**：知道站台網址的人可查看活動、騎行暱稱及抵達紀錄；尚未提供私密活動權限。
- **單一主辦者金鑰**：尚未提供多主辦者帳號或角色管理。
- **刪除打卡點會停用 QR**：原紀錄保留在資料庫，但不再計入進度，也不出現在一般名單或 CSV；目前沒有前台復原功能。
- **活動編輯仍有限制**：尚未提供活動日期修改、活動刪除、關門時間或手動補登打卡。
- **地圖依賴外部服務**：圖磚與 Google Maps 短網址解析需要網路連線。
